21. REPLY DECISION ENGINE — SAFETY FIRST
============================================================

Every incoming message must be classified before generating a reply. Categories:
- greeting / casual conversation
- factual question answerable from verified context
- request for information
- image / screenshot / document / voice note
- invitation / meeting / event / attendance confirmation
- scheduling / availability
- request for decision or approval
- commitment / promise / purchase / payment / booking
- sensitive personal or financial topic
- ambiguous / insufficient context
- urgent or safety-critical

Default policy is DRAFT + USER APPROVAL. Do not send automatically during initial release.

AUTONOMY RULES:
- ChatPilot is an assistant, not the account owner. It must not claim to be human if the product is explicitly operating as an AI agent. Prefer transparent wording where appropriate.
- Never independently accept/decline invitations, confirm attendance, make decisions, promise delivery, agree to money/payment, disclose personal data, book/cancel, or commit the user to a date/time.
- For invitation/confirmation/decision messages, create a draft and mark `requires_approval=true`. If the user is unavailable or has not decided, suggest a neutral holding draft such as “I'll check and let you know” or “Let me confirm and get back to you.” Do not send it without approval in approval mode.
- If user has provided a verified availability rule (e.g., unavailable on a specific date), it may suggest a factual draft but still requires approval unless the user explicitly enables a narrowly scoped automation rule.
- For factual questions, answer only from verified user-approved memory or explicit context. If unknown, ask the user or create a holding draft. Never hallucinate.
- For images/screenshots, use OCR/vision to describe only visible content. Detect sensitive content; do not infer beyond the image. If media is missing from history export, state that the original media was not included.
- For medical, legal, financial, identity, authentication, OTP, password, or high-impact requests, do not auto-send. Avoid storing secrets; escalate to user.
- For ambiguous messages, request clarification instead of guessing.
- Never impersonate the user in ways that mislead a recipient. UI must disclose when AI is drafting; sending remains a user action.

Reply decision object must include:
`category`, `confidence`, `evidence_refs`, `draft_text`, `action` (`draft|hold|require_approval|never_send`), `requires_approval`, `reason`, `missing_information`, and `policy_id`.

Add a Reply Inbox UI with:
- incoming message and media preview
- contact and context
- classification and confidence
- suggested draft
- why this draft was generated
- approve/edit/reject/regenerate controls
- explicit send confirmation
- feedback capture (accepted/edited/rejected)
